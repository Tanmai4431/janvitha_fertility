## 🚶 Step-by-Step Instructions

### Step 1: Install & Linker Verification
1. Output progress bar: `[█░░░░░░░░░] 15%`
2. **Windows Symlink & Permission Compatibility Check**:
   - Check if the agent or user is running on a Windows system.
   - Check if `.npmrc` exists in the workspace root, and if it contains `node-linker=hoisted`.
   - If `.npmrc` is missing or does not contain `node-linker=hoisted` (especially on Windows):
     - Propose creating or updating `.npmrc` at the workspace root with:
       ```ini
       # Force pnpm to use a flat directory structure (similar to npm or Yarn)
       # to avoid symlink permissions errors (ERR_PNPM_CREATING_SYMLINK) on Windows.
       node-linker=hoisted
       ```
     - Explain to the user that this flat hoisting structure avoids Windows symbolic link permission errors (`ERR_PNPM_CREATING_SYMLINK`) during installation.
     - Wait for the file to be written/confirmed.
3. Check if the project has the `node_modules` folder at the root. If not (or if installing/reinstalling is needed):
   - Propose running `pnpm install` at the workspace root.
   - Wait for the user to run the installation successfully.
4. Propose proceeding to Step 2 once the install is done.

### Step 2: Environment Setup (`.env` Configuration)
1. Output progress bar: `[███░░░░░░░] 35%`
2. Configure **Frontend Environment**:
   - Check if `apps/web/.env` exists. If not, copy `.agents/skills/setup-project/templates/env.template` into `apps/web/.env`.
3. Configure **Backend Environment**:
   - Check if `apps/studio/.env` exists. If not, copy `.agents/skills/setup-project/templates/studio-env.template` into `apps/studio/.env`.
4. Explain to the developer in detail how to retrieve the required secret credentials:
   - **PUBLIC_SANITY_PROJECT_ID / SANITY_STUDIO_PROJECT_ID**: Retrieve it from your Sanity Dashboard at [sanity.io/manage](https://www.sanity.io/manage) by selecting your project.
   - **PUBLIC_SANITY_DATASET / SANITY_STUDIO_DATASET**: Usually defaults to `production`.
   - **RESEND_API_KEY**: Create or retrieve an API key from your Resend Dashboard at [resend.com](https://resend.com).
   *(Note: GTM and GA4 tags are configured dynamically inside Sanity CMS/site settings or client.json to follow monorepo dynamic standards, and are intentionally omitted from environment files).*
5. Present the current environment configuration values and prompt the user:
   - *"Would you prefer to:*
     - **Option A**: Provide the values to me here (e.g. `PUBLIC_SANITY_PROJECT_ID=xyz`, `RESEND_API_KEY=re_123`) so I can write them to your `.env` files?
     - **Option B**: Open the files manually in your editor (`apps/web/.env` and `apps/studio/.env`), configure the keys, and let me know when you are done?*"
6. Update the respective `.env` files if the user provides the values (Option A), or wait for their confirmation if they choose Option B.
7. **Cloudflare D1 Database Setup (Manual Schema Creation)**:
   - Explain to the developer that they should create their D1 database manually in their Cloudflare Dashboard:
     1. Go to **Cloudflare Dashboard > Workers & Pages > D1**.
     2. Click **Create Database** (e.g., named `www-starterkit-db`).
     3. Once created, open the database console, copy the SQL commands from [schema.sql](file:///c:/Users/tarak/welcome-webworks/www-starterkit/apps/web/db/schema.sql), paste them into the Cloudflare D1 Console, and click **Execute** to initialize the table structure manually.
     4. Note that wrangler commands should not be run locally.
8. Propose moving to Step 3.

   - Ask the developer to paste their prepared client note.
3. Once pasted:
   - Carefully format and update [CLIENT.md](file:///c:/Users/tarak/welcome-webworks/www-starterkit/CLIENT.md) matching the client profile template.
   - Extract the variables and update [client.json](file:///c:/Users/tarak/welcome-webworks/www-starterkit/client.json). **IMPORTANT**:

     - **Dynamic Field Expansion**: If the client brief contains new/custom attributes (e.g. portfolio items, pricing tiers, certifications, school accreditations, specialized category fields), the agent **must create new fields** inside `client.json` and append them to `CLIENT.md`.
   - **Universal Fallback Pattern Enforcement**: All existing and future frontend pages, sections, and components built for this client **must strictly enforce the priority fallback**: `Value = Sanity CMS field (if populated in Sanity Studio) || client.json value`.
4. **Sanity Studio CMS Settings & Feature Toggles Breakdown**:

### Step 4: Design Ingestion & Monorepo DRY Design System
1. Output progress bar: `[███████░░░] 75%`
2. **Design Specification Prompting**:
   - Ask the developer to paste their prepared visual design system file. The agent MUST ask for and structure the design input using this exact template format:
     ```text
     ---
     name: [Client / Project Name]
     source: [brand direction / reference site / design brief]
     extracted: [YYYY-MM-DD]
     colors:
       background: "#FCFBFA"
       foreground: "#161616"
       primary: "#C60909"
       primary-foreground: "#FFFFFF"
       primary-hover: "#A80707"
       accent-gold: "#F6BE00"
       accent-gold-hover: "#D9A400"
       surface: "#FFFFFF"
       surface-wash: "#FCEDED"
       slate: "#5B5B60"
       slate-soft: "#8A8A90"
       border: "#ECE7E6"
       glass-border: "rgba(198,9,9,0.14)"
     fonts:
       heading: "Cabinet Grotesk"
       body: "Inter"
       mono: "JetBrains Mono"
     ---

     # Design System: [Project Name]
     ## 1. Visual Theme & Atmosphere
     ## 2. Color Palette & Roles
     ## 3. Typography Rules (Families, Hierarchy, Weights, Spacing)
     ## 4. Component Stylings (Buttons, Badges, Glassmorphic Cards, Navigation, Inputs)
     ## 5. Layout Principles (Grid, Whitespace, Alignment)
     ## 6. Design System Notes for Build/Generation
     ```
3. **Ingest and Enforce Design Tokens**:
   - **`global.css`**: Define all tokens as HSL / CSS variables in `:root` (background, foreground, primary, accent, card, radius, borders, glassmorphic shadows).
   - **`tailwind.config.mjs`**: Map the CSS variables, custom colors, fonts (`heading`, `sans`, `mono`), shadows, and border-radii (`sleek`, `modern`, `pill`) into extended Tailwind themes.
   - **`Layout.astro` & Components**: Import font CDNs (Fontshare / Google Fonts), configure header navs, buttons, and component classes to match the design system.
   - **Monorepo DRY Rule**: Every single data point, color, radius, font rule, and glass detail in the provided design system MUST be mapped centrally into `global.css` and `tailwind.config.mjs` so that all current and future components auto-inherit the exact visual identity without code duplication.
4. Propose moving to Step 5.
